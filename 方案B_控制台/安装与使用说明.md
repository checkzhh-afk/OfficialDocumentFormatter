# 方案 B：带按钮的 WPS JSA 控制台

方案 B 是一个带有 WPS JS 宏和复合 `MACROBUTTON` 字段的 `DOCM` 文档。正常使用时，不需要再把 `.js` 文件导入宏编辑器；打开控制台文档后，直接双击文档中的完整动作文字即可执行。

## 正式文件

- `公文格式控制台.docm`：正式控制台，内嵌 `公文格式化控制台WPS宏.js` 和 23 个可执行复合宏字段。
- `公文格式化控制台WPS宏.js`：宏源码主本，用于审查、测试和重新生成控制台。
- `生成公文格式控制台文档.js`：源码更新后重新生成 `DOCM` 的 Node.js 生成器。
- `按钮绑定表.md`：按钮、宏函数和兼容菜单序号对照。
- `示例`：测试文档。
- `历史参考`：旧版模板和早期实验，不作为正式入口。

## 首次使用

1. 先备份待处理公文。
2. 将 `公文格式控制台.docm` 复制到待处理公文所在文件夹。
3. 用 WPS 文字打开这个 `DOCM`。
4. 如果 WPS 提示宏或 JSA 权限，按本机 WPS 安全策略允许该文档运行宏。
5. 看到“公文格式控制台”页面后，确认动作文字以“双击：”开头。
6. 双击完整动作文字执行，例如“双击：同目录一键格式化”或“双击：正文”；不要双击单元格空白处。

控制台必须先保存到文件夹中；只有这样“同目录一键格式化”才能扫描它所在的文件夹。

控制台按钮采用上、左高光和下、右阴影的立体边框。第一次单击时，WPS 可能先选中宏字段；在完整的“双击：操作名称”文字上双击后执行。

## 同目录全文格式化

### 文件夹中只有一个目标文档

双击“双击：同目录一键格式化”。脚本会自动选择同文件夹中唯一的 `.doc`、`.docx`、`.docm`、`.wps` 或 `.wpt` 文件，打开后执行全文格式化。完成后目标文档保持为当前活动文档，便于立即检查结果。

控制台自身不会被处理；即使控制台文件被改名，只要它是当前打开的带控制台宏字段文档，也会从候选列表和手动文件选择结果中排除。名称以 `~$` 开头的 WPS 临时文件，以及其他不支持的文件同样不会被处理。

### 文件夹中有多个目标文档

双击“双击：同目录一键格式化”或“双击：选择同目录目标”后：

1. 脚本自动打开 WPS 原生文件选择框，并定位到控制台所在文件夹。
2. 使用上下方向键移动到目标文件，按 `Enter` 确认；也可以使用鼠标。
3. 仅当当前 WPS 无法使用原生文件选择框时，脚本才列出文件名和序号，要求输入序号。

选择后，“同目录一键格式化”会打开目标并执行全文格式化；“选择同目录目标”只记录目标，不立即格式化。

### Windows、Linux 和云桌面

文件选择框会根据运行环境使用正确的目录分隔符：Windows 使用 `E:\目录\`，Linux 使用 `/home/用户/目录/`。如果 WPS 没有返回控制台文档的 `Path`，脚本会从 `FullName` 中恢复控制台所在目录。

Linux 云桌面本身不影响同目录逻辑，但控制台和目标公文必须是云桌面 Linux 文件系统中已经保存的本地文件。若控制台是从 WPS 云文档、浏览器临时下载目录或未保存的新文档直接打开，WPS 可能只返回虚拟路径或空路径；此时应先把控制台和目标公文保存到同一个本地文件夹，关闭旧控制台，再从该文件夹重新打开最新 `DOCM`。

## 分步全文格式化

适合先选择目标、稍后再处理的情况：

1. 双击“双击：选择同目录目标”。
2. 双击“双击：打开已选目标”。
3. 双击“双击：格式化已选目标”。
4. 双击“双击：查看当前目标”可查看当前记录的文档。

如果目标文档已经手动打开，也可以双击“双击：选择已打开文档”，从已打开的公文中选择目标。

## 局部格式调整

1. 打开需要调整的公文。
2. 在公文中选中文字或完整段落，不要关闭该文档。
3. 切回“公文格式控制台.docm”。
4. 双击“选区格式”区域中的完整动作文字，例如“双击：正文”。
5. 如果同时打开了多个公文，脚本会列出文档名，并显示每个文档是否有选中文字；输入序号后执行。

局部格式按钮直接读取目标文档窗口中保留的选区，不再强制要求先执行“记录选区”。如果同一文档开了多个窗口，脚本优先使用存在实际选中文字的窗口。

常用按钮：

- “正文”：仿宋、三号字、正文缩进和行距。
- “大标题”：宋体、二号字、加粗、居中。
- “一级标题”：黑体、三号字。
- “二级标题”：楷体、三号字、加粗。
- “附件序号”：处理“附件1”“附件2”等序号行。
- “附件标题”：处理附件序号下一行的附件名称。
- “公文页码”：页码为 4 号（14 磅）宋体半角阿拉伯数字，显示为 `—1—`；单页码右对齐并右空一字，双页码左对齐并左空一字；一字线上边缘位于版心下边缘下方 7mm。

“附件1”和附件名称是两个不同段落，应分别使用“附件序号”和“附件标题”。

全文格式化会在每个附件范围内独立识别末尾相邻的落款单位和日期，并按正文落款、成文日期的字体、字号、对齐、缩进和前置空行规则处理。

## 无法使用 DOCM 按钮时

先关闭WPS中已经打开的旧控制台，再重新打开最新生成的 `公文格式控制台.docm`。如果动作名称仍不显示或双击仍不能执行，正式脚本可单独导入 WPS JS 宏项目运行。导入后运行：

1. `ConsoleSyntaxCheck`：检查脚本是否完整加载。
2. `ConsoleRunMenu`：打开序号菜单。

菜单中保留了旧版兼容入口，包括“当前文档设为目标”“记录当前选区”等。按钮方式下通常不需要手动记录选区。

## 更新脚本

修改 `公文格式化控制台WPS宏.js` 后，运行：

```powershell
node ".\方案B_控制台\生成公文格式控制台文档.js"
```

生成器会把最新源码重新嵌入 `公文格式控制台.docm`。更新后的 `DOCM` 需要重新复制到目标文件夹并重新打开。

正式 JS 主本保持纯 ASCII、CRLF 和 ES5 语法。源码中的 `\uXXXX` 是为了兼容 WPS 宏编辑器的编码处理，不要批量还原为中文或另存为 ANSI/GBK。

## 备份和保存

全文或局部格式化会直接修改当前打开的文档，但脚本不会替用户覆盖保存。确认结果后，请使用 WPS 的“另存为”保存新文件，或在确认无误后手动保存原文件。
