# 公文格式化 WPS JS 宏 — 需求与测试说明

## 一、项目背景

本宏运行于 WPS Office JS 宏环境，用于对公文文档自动套用格式规范。支持两种触发模式：
- **全文模式**：一键扫描全文，自动识别各元素并套用格式
- **选区模式**：用户选中文字后，从菜单选择指定格式类型套用

格式规范依据：《公司公文格式主要规范》，未尽事项参照 GB/T 9704-2012。

---

## 二、环境约定

- 运行环境：WPS Office JS 宏，版本 12.8.2.17863（不兼容 VBA，不使用 VBA 语法）
- **菜单挂载方式：ribbonUI**（通过 `customUI.xml` 定义自定义选项卡和按钮，每个按钮绑定对应 JS 函数名；不使用 `Application.AddCustomMenuBar`）
- `customUI.xml` 与 JS 函数文件分开编写，结构独立，便于维护
- 字号单位：磅（pt），3号 = 16pt，2号 = 22pt
- **字体名称**：仿宋 → `"仿宋"`，楷体 → `"楷体"`，黑体 → `"黑体"`，宋体 → `"宋体"`（均不带 GB2312 后缀）
- 字符宽度估算：汉字 = 1个字符宽，半角数字/字母 = 0.5个字符宽，用于署名位置计算
- 段落扫描均跳过以下对象：表格、图片、文本框、分节符所在段落

## 四、元素识别规则

### 4.1 大标题

**扫描范围**：文档前10段（跳过空段）

**识别条件**（须同时满足）：
1. 段落非空
2. 段落对齐方式为居中（`wdAlignParagraphCenter`）
3. 段落文字不以以下序号前缀开头：`一、` `（一）` `(一)` `1.` `1．` `（1）` `(1)`
4. 段落文字末尾不为冒号（全角`：`或半角`:`）
5. 段落文字字数在 5～50 字之间

**多行标题**：连续满足条件的多个段落均视为大标题，一并套用格式。

**格式损坏兜底**：找不到居中标题时，仅当候选标题从文档第一个非空段开始，且其后第一个非空段为冒号结尾的主送单位时，允许按文本特征识别非居中标题。无主送单位时不启用该兜底，避免把开头正文误判为标题。

**格式套用**：2号宋体加粗，居中，固定行距28磅，段前段后0。

**标题前空行**：大标题第一段上方必须且只能保留2个空段；无空段则插入2个，只有1个则补1个，超过2个则调整为2个。

**标题后空行**：大标题最后一段与主送单位之间必须且只能保留1个空段；无主送单位时，大标题最后一段与正文第一段之间必须且只能保留1个空段。无空段则插入1个，多个空段则调整为1个。

---

### 4.2 主送单位

**扫描范围**：大标题最后一段之后，向下扫描

**识别条件**：找到第一个末尾字符为全角冒号`：`或半角冒号`:`的非空段落

**格式套用**：3号仿宋/Times New Roman，两端对齐，左缩进0，首行缩进0，固定行距28磅，段前段后0。

附件说明后紧随的 `2 ...`、`3 ...` 等后续项，按附件说明续行处理，数字起点与上一行首行缩进2字符后的 `附件：1 ...` 中的 `1` 对齐。

---

### 4.3 层级标题

**扫描范围**：主送单位之后、成文日期之前的段落

**识别条件**：正则匹配段落首字符，且同时满足额外条件：
- 段落末尾无句号（`。`或`.`）
- 段落字数 ≤ 40 字

| 层级 | 正则表达式 | 格式 |
|------|-----------|------|
| 一级 | `^[一二三四五六七八九十百]+、` | 3号黑体 |
| 二级 | `^[（(][一二三四五六七八九十百]+[）)]` | 3号楷体加粗 |
| 三级 | `^\d+[.．]` | 3号仿宋加粗 |
| 四级 | `^[（(]\d+[）)]` | 3号仿宋 |

不满足额外条件的段落（有句号或字数>40）视为正文，套正文格式。

---

### 4.4 "一是/二是"句式

**扫描范围**：全文所有段落（全文模式）或选中范围（选区模式）

**识别正则**：`(^|[，。；;、：:\s])([一二三四五六七八九十]+是)(?!否)`

即：段首或逗号、句号、分号、顿号、冒号、空白之后出现的汉字数字+"是"，排除"一是否"等非序列词；支持正文段内连续出现的"一是""二是"。

**字符级格式操作**：
- 每个匹配到的"X是"（含汉字数字和"是"字）：设为**加粗**，其余字体保留该段落已经套用的基础格式
- "是"字之后的所有字符（含紧跟的标点和正文）：不额外加粗，保持段落基础格式
- 使用 Range 或 Run 对象进行字符级拆分操作
- 全文格式化时只修改匹配字符的粗体属性，不重设整段基础格式，避免覆盖层级标题字体

---

### 4.5 成文日期

**识别方式**：只识别独立成行的成文日期，支持 `2024年3月5日` 和 `2026年【】月【】日`。正文段落中夹带的基准日、评估日等日期不作为成文日期。存在附件本体时，只在首个附件顺序号行之前查找成文日期，避免附件中的独立日期覆盖正文落款。

**格式套用**：3号仿宋/Times New Roman，右对齐，右缩进4字符，固定行距28磅，段前段后0。

---

### 4.6 署名

**识别方式**：日期段落的紧上方一段

**距离要求**：正文或附件说明结束后，下方必须且只能空2行，再起排发文机关署名；发文机关署名与成文日期上下相邻，署名写在日期上一行。

**位置精确计算**：

```
字符宽度(pt) = 字号(pt) = 16pt（3号）
右缩进偏移 = 4 × 16 = 64pt

日期文字字符数 = 统计日期字符串字符数
  （汉字计1，半角数字计0.5）
日期文字宽度 = 日期字符数 × 16pt

页面可用宽度 = 页面宽度 - 左边距 - 右边距（单位pt）
日期文字右边界 = 页面可用宽度 - 64pt（右缩进）
日期文字左边界 = 日期文字右边界 - 日期文字宽度
日期文字中心点 = (日期文字左边界 + 日期文字右边界) / 2

署名字符数 = 统计署名字符串字符数（同上规则）
署名文字宽度 = 署名字符数 × 16pt
署名左缩进 = 日期文字中心点 - 署名文字宽度 / 2
```

**格式套用**：3号仿宋/Times New Roman，左对齐，左缩进=计算值，首行缩进0，固定行距28磅，段前段后0。

---

### 4.7 附件说明行

**识别条件**（须同时满足）：
1. 段落以"附件"开头
2. 紧跟阿拉伯数字、空格或冒号（如"附件1 ""附件："）
3. 位置在成文日期之前（排除附件本体中的"附件"字样）

**格式套用**：3号仿宋/Times New Roman，两端对齐，左缩进0，首行缩进0，固定行距28磅，段前段后0。

---

### 4.8 附件本体

**识别条件**：真实分页符或分节符之后，出现独立成行的"附件"或"附件+数字"段落，视为附件本体起始。识别时不以现有左缩进或对齐方式作为前置条件，因为脚本需要修复左缩进错误的原始文档；识别后统一归零左缩进和首行缩进。普通空段不视为分页边界；日期之后但没有分页符的"附件"文字不识别为附件本体。

附件本体内包含两个子元素：

**子元素A：附件顺序号行**
- 特征：段落独立成行，以"附件"开头并可后跟数字；现有缩进错误不影响识别
- 格式：3号黑体，左对齐，左缩进0，首行缩进0

**子元素B：附件标题**
- 特征：附件顺序号行之后的第一个非空段落；正常格式下应居中。为修复已有格式错乱文档，非居中时仍须满足2～50字、无序号前缀、非日期、且不以冒号或句号结尾
- 格式：2号宋体加粗，居中，固定行距28磅，段前段后0

附件顺序号后的第一个非空段落如果是以冒号或句号结尾的说明句，应按正文处理，不识别为附件标题。

附件本体内其余段落套正文格式。

---

### 4.9 正文（兜底）

所有未被识别为上述元素的段落，套正文格式：3号仿宋/Times New Roman，两端对齐，首行缩进2字符，固定行距28磅，段前段后0。

### 4.10 页码

全文模式执行后，各节启用奇偶页不同。页码使用 4 号（14pt）宋体半角阿拉伯数字，格式为 `— 1 —`。奇数页右对齐并右缩进 1 字，偶数页左对齐并左缩进 1 字；不同首页页脚按奇数页规则处理。一字线上边缘位于版心下边缘下方 7mm。页码跨节连续，不按节重新编号。重复执行全文格式化时，不应重复插入 PAGE 域或累积一字线。

---

## 五、全文模式执行流程

```
Step 1：弹窗询问"是否先清除全文格式？"
        是 → 清除所有段落的字符级和段落级格式（跳过表格/图片/文本框/分节符）
        否 → 跳过清除，直接进入识别

Step 2：扫描前10段，识别大标题，套用格式，并规范标题上方2个空段、标题下方1个空段

Step 3：大标题之后向下扫描，识别主送单位，套用格式

Step 4：全文搜索日期正则，定位成文日期段落，套用格式

Step 5：定位署名（日期上方一段），计算左缩进，套用格式
        正文或附件说明与署名之间无空行则插入2个，多个空行则调整为2个

Step 6：识别附件说明行，套用格式

Step 7：识别附件本体（分页后），套用附件顺序号和附件标题格式

Step 8：在主送单位之后、日期之前的范围内，逐段扫描：
        - 匹配层级标题正则 → 套用对应层级格式
        - 匹配"一是/二是"正则 → 字符级加粗处理
        - 其余段落 → 套正文格式

Step 9：设置公文页码：4号宋体、左右一字线、奇右偶左、外侧空1字、距版心下边缘7mm

Step 10：弹窗提示"格式化完成"
```

## 八、边界情况与注意事项

1. **字体回退**：WPS环境如无"楷体"字体，尝试"楷体_GB2312"，如均不存在则记录警告但不报错。
2. **首行缩进单位**：WPS JS中首行缩进设置为字符数时，需转换为磅值（1字符 = 当前字号pt），代码中统一用磅值设置。
3. **右缩进4字符**：同上，转换为 4 × 16pt = 64pt。
4. **空段落处理**：所有识别步骤均跳过空段落（`Paragraph.Range.Text.trim() === ""`或仅含换行符）。
5. **分节符段落**：含分节符的段落跳过格式处理。
6. **多个日期**：存在附件本体时，取首个附件顺序号行之前最后一个符合正则的段落作为成文日期；无附件本体时取全文最后一个符合正则的段落。附件中的日期不得覆盖正文成文日期。
7. **署名左缩进下限**：如计算出的左缩进为负值（署名文字比日期文字宽），则左缩进设为0。
8. **"楷体加粗"兼容性**：部分WPS版本楷体不支持加粗渲染，代码仍写入加粗属性，显示效果以实际环境为准。
